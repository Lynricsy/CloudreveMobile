# iOS 真机验证清单

模拟器与 CI 无法覆盖的行为（后台 URLSession 存活、Share Extension、File Provider）在这里列出，需在真机上逐项验证。
真机构建需要开发者团队签名：App、`plus.ling.opencloudreve.share`、`plus.ling.opencloudreve.fileprovider` 三个 target 都要开启 App Group `group.plus.ling.opencloudreve` 与 Keychain 共享组 `plus.ling.opencloudreve.shared`。

## File Provider（系统“文件”集成）

前置：服务端可访问；准备两个账户（A、B，可在不同站点），A 的“我的文件”里有若干目录（其中一个超过 200 项）、一张图片、一个 PDF。

1. **域的增删**
   - 登录 A → 打开“文件”App →“位置”中出现 `<A 昵称> @ <host>`（若未出现：“浏览”页右上 `…` → 编辑，打开 OpenCloudreve）。
   - 再添加账户 B → 出现第二个位置 `<B 昵称> @ <host>`。
   - 在 App 内登出 B → B 的位置消失；A 仍在。
2. **浏览与分页**
   - 进入 A 的根目录：条目、大小、修改时间与 App 内一致；目录可进入。
   - 进入超过 200 项的目录并滚动到底：全部条目都加载出来（游标分页 / 页码分页均可）。
   - 断网后再进入已浏览过的目录：显示系统缓存的条目；进入从未浏览过的目录：提示无法连接服务器。
3. **打开内容**
   - 点按图片、PDF：下载后用系统预览打开；再次打开不重复下载。
   - 打开“分享到我的文件”的软链接文件：内容来自链接目标。
4. **创建**
   - 新建文件夹 → App 内同一目录出现该文件夹。
   - 从“照片”或其它位置拷贝一个文件（≥ 50 MB）到 A 的目录 → 上传完成后 App 内可见，大小一致；Web 端可预览。
   - 再拷贝同名文件 → 系统自动改名（如 `a 2.jpg`）后上传，不覆盖原文件。
5. **修改**
   - 重命名文件、目录 → App/Web 端名称同步。
   - 在 A 内把文件拖到另一个目录 → 服务端移动成功。
   - 用支持就地编辑的 App（如 Pages/文本编辑器）修改一个 txt 并保存 → 服务端生成新版本（App 内“版本”可见），文件 id 不变。
6. **删除**
   - 删除文件 → 进入 Cloudreve 回收站（App 内“回收站”可见，可还原），不是彻底删除。
7. **主 App 联动**
   - 保持“文件”App 打开 A 的某目录，在 OpenCloudreve App 内对该目录新建文件夹 / 重命名 / 删除 → 切回“文件”App，几秒内列表刷新。
8. **登录失效**
   - 在 Web 端修改 A 的密码（使 refresh token 失效）→ 在“文件”App 中刷新 A：提示需要登录（notAuthenticated）；回 App 重新登录后恢复。
9. **权限位**
   - 浏览“与我共享”之外不可写的位置（如管理员禁止上传的用户组）：系统不提供新建/拷入/重命名操作。

已知限制：
- 服务端没有增量变更流，系统每次收到刷新信号都会重新完整枚举工作集（最近浏览过的 50 个目录）。
- 上传、下载在扩展进程内同步完成（整片读入内存，内存占用约为“分片大小 × 并发数”）；大文件期间切走“文件”App 可能被系统挂起，回来后由系统重试。
- 扩展创建的传输任务完成后即从传输列表删除，主 App 的传输页不显示这些任务。
